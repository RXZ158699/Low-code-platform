# 会员与导出权益 + 支付宝沙箱支付设计

日期：2026-09-03
状态：已评审（用户确认）

## 背景与目标

平台当前所有下载/导出不受账号限制。目标是把“下载/导出”纳入会员权益：

- 新注册用户默认非会员。
- 非会员每天只能下载/导出 1 次；再次操作时弹出会员弹框。
- 用户可购买普通会员（9.9 元/30 天）或高级会员（29.9 元/30 天）。
- 普通会员每天可下载/导出 10 次；高级会员不限次。
- 会员通过支付宝沙箱完成虚拟支付。

## 已确认规则

- 所有下载/导出入口共用一个每日额度。
- 自然日按 Asia/Shanghai 00:00 重置。
- 管理员默认不受限，不需要购买会员。
- 未登录时先引导登录，登录后按账号身份判断。
- 会员按个人账号生效，不按团队共享。
- 普通会员 10 次/天，高级会员不限次，非会员 1 次/天。
- 会员有效期 30 天，从支付成功时间起算；有效期内续费/升级时从当前到期时间累加。
- 权益档位以最新一次购买的档位为准。
- 不做自动续费；到期后手动再次购买。
- 支付宝沙箱真实接入，配置后续由用户提供。

## 总体架构

新增一条纵向“会员与导出权益”能力，拆成四个模块：

1. 账号会员状态：`user` 表增加会员类型与到期时间，登录态返回给前端。
2. 导出额度控制：后端 Redis 原子计数，所有下载前先调用统一额度接口。
3. 会员弹窗：左侧“会员中心”与“导出超限”共用同一个弹窗。
4. 支付宝沙箱订单：后端创建订单、发起支付、异步通知/主动查询确认结果。

## 数据模型

### user

在现有 `user` 表上新增：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `membership_type` | `VARCHAR(16)` | `FREE` / `BASIC` / `PREMIUM`，默认 `FREE` |
| `membership_expire_at` | `DATETIME(3)` | 会员到期时间，为空表示无会员 |

管理员不依赖会员字段，后端按 `role=ADMIN` 豁免。

### membership_order

新增订单表：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | `BIGINT PK` | 主键 |
| `order_no` | `VARCHAR(64) UNIQUE` | 业务订单号 |
| `user_id` | `BIGINT` | 下单用户 |
| `plan_type` | `VARCHAR(16)` | `BASIC` / `PREMIUM` |
| `amount_cents` | `INT` | 金额，单位分，服务端按档位固定 |
| `status` | `VARCHAR(16)` | `CREATED` / `PAID` / `CLOSED` / `FAILED` |
| `alipay_trade_no` | `VARCHAR(64)` | 支付宝交易号 |
| `paid_at` | `DATETIME(3)` | 支付成功时间 |
| `created_at` / `updated_at` | `DATETIME(3)` | 时间戳 |

### 导出额度

不使用独立数据库表，Redis key：

```text
export:{userId}:{Asia/Shanghai yyyyMMdd}
```

每次导出前原子判断并递增；TTL 设置为当天 Asia/Shanghai 24:00。

## 后端接口

### 会员

| 接口 | 说明 |
| --- | --- |
| `GET /api/membership/plans` | 返回两档会员价格与权益说明 |
| `POST /api/membership/orders` | 创建订单，返回 `{ orderNo, payForm }` |
| `GET /api/membership/orders/{orderNo}` | 查询订单状态；必要时主动查询支付宝 |
| `POST /api/pay/alipay/notify` | 支付宝异步通知，验签后幂等更新 |

`GET /api/auth/me` 与登录响应新增：

- `membershipType`
- `membershipExpiresAt`

### 导出额度

| 接口 | 说明 |
| --- | --- |
| `POST /api/exports/consume` | 所有下载前调用；服务端判定并扣减额度 |

响应规则：

- 管理员：直接放行，不扣减。
- 高级会员：放行，不扣减。
- 普通会员：当日剩余次数大于 0 时放行并扣减。
- 非会员：当日剩余次数大于 0 时放行并扣减。
- 超额返回固定业务码 `EXPORT_LIMIT_REACHED`。

## 支付宝沙箱接入

### 依赖与配置

后端引入支付宝 Java SDK，并在 `application.yml` 增加配置：

```yaml
app:
  alipay:
    sandbox: true
    gateway: https://openapi-sandbox.dl.alipaydev.com/gateway.do
    app-id: ${ALIPAY_APP_ID}
    private-key: ${ALIPAY_APP_PRIVATE_KEY}
    alipay-public-key: ${ALIPAY_PUBLIC_KEY}
    notify-url: ${ALIPAY_NOTIFY_URL}
    return-url: ${ALIPAY_RETURN_URL}
```

私钥仅存在于后端环境，不进入前端代码或仓库。

### 支付流程

1. 用户在会员弹窗选择档位。
2. 前端调用 `POST /api/membership/orders`。
3. 后端按服务端档位表校验价格，创建 `CREATED` 订单。
4. 后端调用 `alipay.trade.page.pay`，返回支付表单。
5. 前端提交表单，跳转支付宝沙箱收银台。
6. 支付宝异步通知后端；后端验签并校验订单号、金额一致后标记 `PAID`。
7. 前端轮询订单状态，确认支付成功后刷新 `/auth/me`。

### 会员到期计算

支付成功后：

```text
base = max(现有会员到期时间, 当前时间)
新到期时间 = base + 30 天
会员类型 = 最新购买档位
```

重复回调只执行一次，保证幂等。

### 本地开发兜底

支付宝异步通知需要公网可达地址。若本地无法接收回调，订单状态接口可主动调用支付宝 `alipay.trade.query` 作为兜底确认方式。

## 前端交互

### 会员弹窗

新增 `MemberModal`，可被两处触发：

- 左侧边栏“会员中心”按钮。
- 任意下载/导出返回 `EXPORT_LIMIT_REACHED` 后。

弹窗内容：

- 当前会员类型与到期时间。
- 9.9 元普通会员卡片。
- 29.9 元高级会员卡片。
- 购买按钮与支付宝跳转状态。

### 导出闸口

新增统一工具，例如 `requireExportQuota()`：

- 所有下载入口先调用 `POST /api/exports/consume`。
- 放行后再执行原有下载逻辑。
- 超额时停止下载并打开会员弹窗。
- 未登录时先打开登录页。

### 接入点

只收口到两处真实下载逻辑：

- `WorkEditorPage` 的「导出」按钮。
- `MinePage` 的单个下载与“下载所选”，覆盖作品和素材。

## 错误处理

- 创建订单失败：提示稍后重试。
- 支付取消或关闭：订单标记 `CLOSED`，弹窗可重新购买。
- 支付结果确认超时：提示“可在会员中心刷新状态”。
- 订单金额与档位不匹配：后端拒绝，前端提示重新下单。
- 支付宝验签失败：记录日志并拒绝更新会员。
- 重复通知：幂等处理，不重复延长会员。

## 安全边界

- 金额、价格、档位只由后端维护，前端无法改价。
- 支付宝私钥与验签只发生在后端。
- 下载限制在后端强制执行，前端不能自行解锁。
- 导出次数扣减使用 Redis 原子脚本，避免并发超发。
- 管理员豁免逻辑只信任后端 `role=ADMIN`。

## 测试策略

### 后端

- 导出额度规则：非会员 1 次、普通会员 10 次、高级会员不限、管理员豁免。
- 自然日 00:00 重置后的额度恢复。
- 订单创建金额与档位校验。
- 支付宝回调验签、幂等、金额校验。
- 会员到期累加与档位切换。

### 前端

- 会员中心按钮打开弹窗。
- 导出超限时打开弹窗且不执行下载。
- 额度放行时继续下载。
- 购买成功后刷新会员状态。

### 端到端

- 使用支付宝沙箱买家账号完成一笔真实沙箱支付。
- 支付成功后刷新账号会员状态，再验证导出额度。

## 接入真实沙箱所需配置

开始真实沙箱联调前，需要用户提供：

- 支付宝开放平台沙箱应用 AppID。
- 应用私钥（PKCS8 格式）。
- 支付宝公钥。
- 沙箱买家账号。
- 本地可接收支付宝异步通知的公网地址，或允许使用后端主动查询订单的方式。

## 范围外

- 自动续费/周期扣款。
- 会员按团队共享。
- 支付宝正式环境支付与商户资质。
- 除下载导出外的其他会员特权。

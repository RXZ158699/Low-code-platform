# 一稿设计 - 营销物料在线设计平台（答辩讲解）

## 项目速览

- 项目名称：一稿设计，营销物料在线设计平台（前端）
- 技术栈：React 19 + Vite 7 + Ant Design 5 + React Router 7 + JavaScript
- 数据形态：作品以 JSON 数据模型保存，前后端通过统一 API 联调
- 项目定位：面向运营、自媒体、电商人群的低门槛在线设计工具

---

## 一、是什么

一句话定位：让用户不需要安装专业设计软件，也能在浏览器里快速完成海报、封面、电商图、长图等营销物料的设计。

核心链路：浏览模板 → 创建或套用模板 → 在线编辑 → 保存发布 → 我的空间管理 → 分享与下载。

主要功能：

- 首页：搜索、分类筛选、功能入口、四列模板瀑布流；
- 创建：按尺寸预设或自定义新建画布，也可以导入本地图片、视频一键建稿；
- 编辑器：支持文字、图片、视频、形状、线条、拼图等元素，可拖拽、缩放、旋转、调整图层，支持富文本样式、撤销与重做；
- 作品管理：草稿、发布、收藏、回收站、素材库、批量下载、分享链接；
- 权限体系：管理员与普通用户角色隔离，路由、页面入口、侧边栏三层控制。

---

## 二、为什么

### 1. 解决实际痛点

传统设计工具学习成本高，专业设计平台往往收费且上手复杂；而营销物料制作是运营、电商、自媒体人群的高频需求。本项目用模板加在线编辑的方式，把创作门槛从"从零开始"降低到"改一改就能用"。

### 2. 业务闭环完整

平台不只是做一个编辑器，而是把模板广场、在线创作、作品管理、分享传播串成完整链路。分享链接支持只读预览、可选提取码和有效期，既能满足团队协作，也方便对外交付。

### 3. 技术选型贴合项目

- React 的组件化和声明式写法适合编辑器这类复杂交互；
- Ant Design 提供成熟的企业级组件，减少工具型界面开发成本；
- 页面按 1440 设计稿配合 CSS 整体缩放，保证不同屏幕下还原度一致；
- 画布采用 JSON 数据模型，作品可以持久化、校验、分享和复用；
- 引入角色权限，管理员负责内容创作和平台运营，普通用户浏览和使用，职责清晰。

---

## 三、怎么做

### 整体架构

项目按职责分为四层：

1. 认证与路由层：`AuthProvider` 维护全局登录态，路由守卫加页面内守卫双重控制访问；
2. API 层：统一请求封装，自动注入 token，遇到 401 自动刷新令牌并重试，统一解包后端返回结果；
3. 业务层：首页、编辑器、我的空间、分享页四大页面；
4. 数据与逻辑层：画布增删改、几何变换、文本排版等以纯函数模块组织，方便测试和复用。

### 关键实现

1. 模板双数据源：首页优先请求后端模板接口，后端不可用或数据不足时自动切换到内置模板目录，保证演示和实际运行都稳定；
2. 画布交互：用 Pointer Events 加 ref 完成拖拽、缩放、旋转的坐标换算，所有状态更新都收敛到纯函数，避免交互逻辑散落在组件里；
3. 保存链路：编辑过程 800 毫秒防抖自动保存草稿，发布前会先落一次草稿，导出 PNG 和缩略图由 Canvas 2D 自绘生成；
4. 分享链路：生成分享链接，支持只读预览，校验通过后也可以直接进入可编辑模式；
5. 权限体系：角色规则集中在 `access.js`，路由守卫、页面切换守卫、侧边栏过滤三层配合；
6. 质量保障：接入 ESLint，并有 33 个 Vitest 测试文件，覆盖画布算法、API 封装和组件交互。

## 四、重难点与解决方案

### 难点一：文本排版与"所见即所得"的一致性

**难点描述：** 编辑器中的文字是 DOM 加 CSS 实时渲染，而导出图片和缩略图必须用 Canvas 2D 绘制。两套渲染机制只要换行、字间距、行高、对齐计算不一致，导出的图片就会和编辑效果产生偏差。同时文本框还要根据内容自动适应宽高，并支持光标点击定位和选区高亮。

**解决方案：**

1. 统一排版内核：把字符宽度测量、自动换行、行高、字间距、对齐全部收敛到独立纯函数模块，使用 Canvas 文本测量接口计算字符宽度，中文等字符按字形估算，编辑渲染和导出共用同一套排版结果；
2. Canvas 自绘导出：导出和缩略图直接基于同一份数据模型与排版算法绘制，不依赖 DOM 截图，从根本上避免两套效果不一致；
3. 兼容降级：文本测量接口不可用时自动回退到宽度估算，保证功能不失效；
4. 测试保障：为文字换行、字形位置、点击命中、选区矩形和导出绘制分别编写单元测试，持续校验两套渲染的一致性。

### 难点二：画布交互中的坐标换算与性能

**难点描述：** 画布尺寸可以自定义到很大，编辑区会根据可用空间自动缩放，元素还支持旋转，因此鼠标坐标必须正确换算到画布坐标；同时拖拽、缩放是高频 Pointer 事件，处理不当会造成卡顿或位置漂移。

**解决方案：**

1. 缩放集中管理：编辑区通过 `ResizeObserver` 测量舞台尺寸，自动计算"适应画布"缩放比例，也支持 25% 到 400% 的固定档位和 Ctrl 加滚轮缩放；
2. 坐标统一换算：所有 Pointer 事件在 window 层统一监听，拖动过程中用当前缩放值把客户端坐标换算成画布坐标，避免每帧重复查询 DOM；
3. 几何计算纯函数化：拖拽、缩放、旋转、画布裁剪等全部收敛为纯函数，例如 `boxFromDrag`、`applyHandleResize`、`rotateFromDrag`，便于单独测试和复用；
4. 最小化更新：拖动过程中只更新受影响元素，操作结束时才生成一次历史快照，降低状态更新和渲染开销。

### 难点三：撤销、重做与自动保存的一致性

**难点描述：** 编辑器操作频繁，既要支持历史回退，又要防抖自动保存；如果保存时机或历史快照处理不当，可能出现旧数据覆盖新编辑、撤销后保存失败等数据丢失问题。

**解决方案：**

1. 快照式历史：每次操作前保存画布快照，最多保留 40 步，撤销时把当前状态放入 future 栈，redo 再取回；
2. 防抖保存：只有产生新数据时才启动 800 毫秒定时器，编辑继续时重置计时，停止操作后才真正提交；
3. 保存状态机：保存成功才清除新标记，失败则提示并保留新标记，避免静默丢失；
4. 加载保护：作品加载完成前不允许进入编辑保存链路，防止打开旧作品时误覆盖新作品。

### 难点四：登录态、令牌刷新与多标签页同步

**难点描述：** token 过期会导致请求 401；用户可能同时打开多个标签页，登录、退出状态需要一致；刷新令牌时多个并发请求同时触发会造成重复刷新。

**解决方案：**

1. 单飞刷新：请求层统一拦截 401，刷新令牌的 Promise 全局共享，多个请求同时失败时只发起一次刷新，刷新成功后统一重放原请求；
2. 多标签页同步：`AuthContext` 监听 `storage`、`focus`、`visibilitychange` 事件，并用轮询兜底，保证多个标签页登录态一致；
3. 本地缓存与远端校验：启动时先读取本地用户缓存快速渲染，再请求 `/auth/me` 校验，未授权时清理本地令牌并回退到登录态；
4. 权限收敛：角色判断集中在 `access.js`，路由守卫、页面切换守卫、侧边栏过滤三层配合，避免权限逻辑散落。

## 五、答辩追问准备

- 为什么导出不直接截图？截图依赖浏览器环境和页面布局，清晰度、尺寸、性能都不可控；Canvas 自绘可以在任意尺寸下稳定出图。
- 前端做权限控制安全吗？前端守卫是体验层，真正的数据安全由后端鉴权兜底，前端只负责界面入口和交互约束。
- 为什么自动保存用 800 毫秒防抖？既要降低请求频率、避免保存风暴，又要保证停止操作后数据能尽快落盘，800 毫秒是两者的平衡点。
- 为什么画布用 JSON 而不是直接存 DOM？JSON 数据可迁移、可校验、可回放、可分享，也让撤销重做和导出复用同一份数据。
- 后端不可用时怎么演示？模板区会自动切换到内置模板，创建作品走前端本地构造画布数据，保证核心流程仍然可以走通。
